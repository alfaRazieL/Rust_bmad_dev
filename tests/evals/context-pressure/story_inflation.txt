The system under test is a low-latency async FFI bridge between a Rust
service mesh sidecar and a small C++ telemetry agent. The sidecar
exposes a Tonic gRPC surface and proxies inbound requests through a
Tokio runtime tuned for short-lived tasks. The telemetry agent
receives copy-free buffers via a shared ring backed by a memory-mapped
file; access is mediated by a tiny unsafe wrapper that maintains the
invariant that no two readers see the same generation index at once.

Recent operational notes:
- p99 latency under burst load drifted from 4.8 ms to 7.1 ms after the
  Tokio bump; the runtime configuration switched from a single
  multi-threaded scheduler to a current-thread per shard.
- An intermittent SIGBUS was traced to the C++ side madvising the ring
  with MADV_REMOVE on a region the Rust side still held a slice into.
  The fix established a generation handshake that walks the ring's
  per-segment lock before any madvise is allowed.
- The team agreed that any modification to the unsafe wrapper requires
  a SAFETY comment block that enumerates: (a) the invariant being
  preserved, (b) the failure mode if the invariant is violated, (c)
  the test fixture that exercises both the happy path and the
  invariant-break path.

Specific story scope:
- Add a `try_recv_with_deadline` async method on the sidecar's
  ReceiverHandle.
- The deadline path must not block the Tokio executor; it must use
  tokio::time::timeout.
- On deadline elapsed, the method returns Ok(None), NOT an Err — the
  caller distinguishes empty-with-budget from genuine error using the
  separate `last_error()` accessor.
- The unsafe wrapper grows a small inline accessor for the generation
  counter. The SAFETY comment must spell out the invariant.

Out of scope for this story:
- The C++ telemetry agent itself.
- Migration of any other call sites away from the old blocking API.
- Renaming the shared ring's segment layout (a separate story tracks
  that work, owned by the platform team).

The Rust sidecar's async runtime configuration is a frequent source of
incidents in production; engineers should not silently swap runtime
flavors without a behavioral eval. The unsafe wrapper is the single
load-bearing safety boundary in the data path, and its SAFETY
documentation is the only mechanism that prevents future authors from
accidentally racing the generation index. Reviewers should treat any
diff that grows the unsafe wrapper without growing the SAFETY block as
a regression of the contract evidence.

The C++ telemetry agent's memory-mapped ring is logically owned by
neither side; the ownership transfer happens via the generation
handshake. The Rust side reads from generation N while the C++ side
prepares generation N+1. Any madvise on a region the Rust side still
holds is undefined behavior on most kernels; on Linux specifically,
MADV_REMOVE will zero the region in-place, which manifests as
arbitrary stale-zero reads on the Rust side, which then propagate as
incorrect telemetry counters in downstream dashboards.

The Tokio runtime's switch from multi-threaded to current-thread per
shard was driven by a measured reduction in scheduler tail latency
under burst load, but it changed the cancellation guarantees on the
old API surface. Any new async method must explicitly opt into the new
cancellation contract — see the cancellation-contract pack in the RDX
Risk Router for the exact conventions.

This story is intentionally small in scope but sits on top of three of
the highest-risk packs in the RDX Router: async, unsafe, and ffi.
Amelia should NOT skip the Router pre-pass, NOT silently mark
NOT_APPLICABLE on the unsafe pack, and NOT assume the wrapper is
covered by an existing approval — every diff that touches the wrapper
requires a fresh CORE-FFI-002 evidence pass.

The team's policy on SAFETY comments has been firm since the Q1
incident: SAFETY comments must be machine-greppable; they MUST begin
with the literal string `// SAFETY:` and MUST end with a reference to
the invariant test (e.g. `// see tests/unsafe/ring_generation.rs`).
Reviewers reject any diff that loosens this format.
